```
npm install
npm run dev
```

`npm run dev` starts `wrangler dev --test-scheduled` and fires the cron
handler every 10 seconds (`scripts/dev.mjs`), because wrangler never runs cron
triggers on its own and batches are ingested and processed only by that
handler. `TICK_SECONDS=5 npm run dev -- --port 8790` changes the interval and
passes `--port` through to wrangler. `npm run dev:server` runs the server
without the ticker; trigger a tick by hand with
`curl "http://localhost:8787/__scheduled?cron=*+*+*+*+*"`.

## Database

Everything outside `src/db` talks to the database only through the
`Repositories` interface in `src/db/store.ts`. Each driver implements it with
its own Drizzle schema and SQL dialect:

| Driver     | Folder            | Connection                      | Migrations          |
| ---------- | ----------------- | ------------------------------- | ------------------- |
| `postgres` | `src/db/postgres` | `DATABASE_URL` secret (Supabase) | `drizzle/postgres`  |
| `d1`       | `src/db/sqlite`   | `DB` D1 binding in wrangler.jsonc | `drizzle/sqlite`   |

### Switching drivers

Set `DB_DRIVER` in `wrangler.jsonc` (`vars`) to `postgres` (default) or `d1`,
then `npm run cf-typegen`. For a one-off local run:

```
npx wrangler dev --var DB_DRIVER:d1
```

Drivers do not share data. Column names are identical in both schemas, so a
table-by-table copy is possible, but nothing does it automatically.

### Migrations

Postgres (applied directly through drizzle-kit):

```
npm run db:pg:generate   # after editing src/db/postgres/schema.ts
npm run db:pg:migrate
```

D1 (SQL generated by drizzle-kit, applied by wrangler):

```
npm run db:d1:generate        # after editing src/db/sqlite/schema.ts
npm run db:d1:migrate:local   # local dev database (.wrangler/state)
npm run db:d1:migrate:remote  # the database_id in wrangler.jsonc
```

Keep the two schema files in sync: every column added to one must be added to
the other, and the compile-time checks in each driver's `repositories/index.ts`
fail if a driver's rows stop matching the shared entity types.

### D1 limits

D1 binds at most 100 parameters per statement, so the sqlite driver splits bulk
writes into small statements and sends them with `db.batch()` (one round trip
and one transaction per group). See `MAX_PARAMS` in `src/db/sqlite/client.ts`.

### D1 usage meter (ENVIRONMENT=DEV)

D1 bills rows read and rows written, not queries. With `ENVIRONMENT=DEV` and
`DB_DRIVER=d1`, the binding is wrapped (`src/db/sqlite/metrics.ts`) and every
cron tick and request logs its cost plus a running total for the isolate:

```
[d1] cron tick: 14 stmts, read 3.1k, written 150 | total: read 2.10M, written 412.0k
```

Run a batch to completion locally and read the last total to see what it would
cost in production. Totals reset when `wrangler dev` reloads the worker.

### Tests

`npm test` runs the repository suite against both drivers in memory: PGlite for
Postgres (using the real `drizzle/postgres` migrations) and libsql for SQLite
(using `drizzle/sqlite`). No external database is needed.

## Mock AI (ENVIRONMENT=DEV)

Set `ENVIRONMENT=DEV` to replace every AI provider with `MockAiClient`
(`src/ai/mock.ts`): no API keys or network, and a deterministic verdict per
word (about 15% marked misspelled, with an occasional disagreeing model so
"Review Needed" shows up). `wrangler.jsonc` ships `ENVIRONMENT: "PROD"`;
`.dev.vars` overrides it locally, or pass `--var ENVIRONMENT:DEV` to
`wrangler dev`.
